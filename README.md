# Week 9 — Serialize, Track & Serve the Churn Model

This repository packages and serves the **already-fitted Week 7 Telco churn pipeline**. It does not retrain the model.

## Project structure

```text
week9_churn_serving/
├── data/raw/Telco-Customer-Churn.csv
├── src/
│   ├── serialize_model.py
│   └── log_experiment.py
├── models/
│   ├── churn_pipeline.joblib
│   └── churn_pipeline.skops       # generated by serialize_model.py
├── tests/test_api.py
├── artifacts/week7_model_metrics.json
├── mlruns/                        # generated by log_experiment.py
├── main.py
├── requirements.txt
└── README.md
```

## Reproducibility and frozen model

- Week 7 pipeline artifact: reused as-is; no refitting in Week 9.
- Model random seed: `42` (recorded in the fitted XGBoost classifier).
- Week 7 split seed: `42`; tuning used stratified 5-fold CV.
- Serving threshold: `0.3251224160194397`.
- Input preprocessing is inside the serialized sklearn Pipeline. The API sends raw feature values to that pipeline and does not duplicate preprocessing.
- Unknown categorical values are accepted and safely ignored by the fitted `OneHotEncoder(handle_unknown="ignore")`.

## Setup

Python 3.11 is recommended. From this directory:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Serialize the frozen pipeline

`models/churn_pipeline.joblib` is included. To additionally create the skops serialization:

```bash
python src/serialize_model.py
```

**Security trade-off:** joblib is convenient and efficient, but loading a malicious pickle-based artifact can execute arbitrary code. Only load trusted, integrity-checked joblib files. skops avoids blindly executing arbitrary pickle payloads and exposes untrusted types for review; inspect the generated `models/skops_untrusted_types.json` and explicitly trust only types whose origin you have verified. XGBoost is a third-party estimator and may require additional compatibility/trust review.

## Log local MLflow run

```bash
python src/log_experiment.py
mlflow ui --backend-store-uri ./mlruns
```

This creates a local `mlruns/` tracking store, logs the Week 7 parameters and holdout metrics, and attaches the exact serialized pipeline as an artifact. No remote tracking server is used.

## Run API

```bash
uvicorn main:app --reload
```

- Health check: `GET http://127.0.0.1:8000/health`
- Prediction: `POST http://127.0.0.1:8000/predict`
- Interactive docs: `http://127.0.0.1:8000/docs`

The endpoint returns `churn_probability`, `prediction` (`Yes`/`No`), and the fixed Week 7 decision threshold.

## Test

```bash
pytest -q
```

Tests cover valid input, missing fields, invalid types, out-of-range values, unseen categories, and a known-input probability regression check.

## API input schema

The endpoint requires all 19 model features: `gender`, `SeniorCitizen`, `Partner`, `Dependents`, `tenure`, `PhoneService`, `MultipleLines`, `InternetService`, `OnlineSecurity`, `OnlineBackup`, `DeviceProtection`, `TechSupport`, `StreamingTV`, `StreamingMovies`, `Contract`, `PaperlessBilling`, `PaymentMethod`, `MonthlyCharges`, `TotalCharges`.

`customerID` and `Churn` are intentionally excluded.
